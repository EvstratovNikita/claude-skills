# Выпуск бизнес-документалки без лица: процесс, правила, ошибки

Собрано по выпуску 1 (Costco, v1–v5, октябрь 2026). v5 владелец принял как «достойное», это планка качества. Общаться с владельцем по-русски, ролик на английском для США. Бюджет нулевой: только бесплатные инструменты, платные генерации (Higgsfield и т. п.) не используем.

## Где что лежит (папка проекта /mnt/project-files)
- `assets/toolkit/ep1_source.tar.gz`: весь код выпуска 1 (Remotion src, blender/*.py, tools, aud, скрипты рендера, BRIEF.md для QA-агентов). Начинать новый выпуск с распаковки в `/tmp/claude-0/work/epN`, а не с нуля.
- `assets/toolkit/ep1_library_public.tar`: готовая библиотека `public/` (спрайты Blender: хот-дог, кола, карты, коробка, курица, машина; art/, street/, tex/, шрифты). Переиспользовать.
- `assets/blender/`, `assets/stock/`: ранние версии скриптов и сток склада.
- `knowledge/video_best_practices.md`: дизайн-код, замеры Blender, конспект 7 маршрутов. Прочитать перед стартом.
- Готовые выпуски: `episodeN/episodeN_<тема>_vK.mp4` + `episodeN_captions.srt` + `youtube_upload.md` + `thumbnails/`. Старые версии удалять только по слову владельца.

## Среда
- Облако: 4 ядра CPU, без GPU. Сеть пускает PyPI, npm и GitHub releases; стоковые сайты, polyhaven и пр. закрыты. Сток владелец скачивает сам и кладёт файлом.
- Контейнер эфемерный: всё ценное (код, ассеты, итог) копировать в /mnt/project-files. Рендеры могут умереть при перезапуске контейнера: писать прогресс в лог и уметь продолжить главу.
- Папка проекта не принимает файлы ~900 МБ (ссылка тихо умирает: «This file is no longer available»). Финал держать ≤ ~300 МБ.
- Диск ограничен: бандл Remotion копирует public/ (~0.6 ГБ) на каждый запуск; удалять бандлы после рендера (stills.mjs/render.mjs уже делают). Удалять промежуточные mp4 после сборки.

## Конвейер
1. **Тема и сценарий.** Структура хитов: парадокс знакомого бренда, главный крючок в первые 10 с, обещание ответа в конце, 3–4 открытые петли, 15–20 мин. Все цифры из первоисточников (годовые отчёты), спорные факты перечислить владельцу перед публикацией. Иллюстративные цены подписывать как условные.
2. **Озвучка.** Kokoro ONNX (`kokoro-v1.0.onnx`, `voices-v1.0.bin` с GitHub thewh1teagle/kokoro-onnx), голос `am_michael`, speed 0.95, по сегментам `script.json` (`tts.py`). Проверка: faster-whisper `base.en` (`asr.py`). Слова: выравнивание pocketsphinx со словарём произношений имён (`align.py`), затем `build_timeline.py` -> `src/timeline.json` (паузы между сегментами 0.5 с, между главами 2.4–3.6 с, после вопросов ≥0.7 с).
3. **Анимация.** Remotion 4, 30 fps, каждая глава `src/ch/<ch>.tsx` со списком `SceneSpec` (якоря вида `seg@word#n+N`), отдельная точка входа `src/solo/<ch>.tsx` на главу. Всё движение от кадра и якорей слов (`T.w(seg, word)`), никаких CSS-анимаций.
4. **3D-герои.** Blender headless (Cycles CPU + OIDN) спрайтами, см. ниже.
5. **Звук.** `aud/mix.py`: голос + приглушаемая музыка + SFX из списков `<CH>_SFX` и авто-свуши на склейках, loudnorm в два прохода до −14 LUFS, TP −1. После любых сдвигов сцен перезапускать микс.
6. **Рендер по главам** (`render_job2.sh <ch>`): `GL=null`, `--disable-gpu --disable-gpu-compositing` (CPU-растр в ~12 раз быстрее swangle для 2D), `SCALE=4/3` (мастер 2560×1440), CRF 12, JPEG 100, concurrency 4. Склейка `ffmpeg concat -c copy`.
7. **Доставка.** Двухпроходный libx264 medium `-b:v 1950k -maxrate 3500k -bufsize 7000k`, aac 192k 48 кГц, `+faststart` -> ~280 МБ на 17 мин в 1440p. Скопировать в папку проекта, подождать ~10 с, проверить размер и ffprobe, приложить через attached_outputs.
8. **Упаковка.** 3 названия, описание с таймкодами глав, теги, закреп, .srt с цифрами цифрами, 3 обложки для «Test & compare». Обложки: эмоция и конфликт без слов, 2–4 слова крупно, проверять ложные цифры и кривые буквы в сгенерированных обложках.

## Дизайн-правила (нарушения = дефекты, владелец их видит)
- **Без мёртвых стартов.** Через ≤0.5 с после начала сцены главный визуал уже строится (рисуется, едет, считает). Привязанные к словам удары остаются на словах, а установочное движение переносится в начало. Маленькая строка текста над пустым кадром 2+ с = дефект.
- **Без заморозок.** Нет участков 3+ с без движения: дрейф, параллакс, пульс, тикающий счётчик.
- **Цифры не висят на нуле.** Число появляется в момент, когда его произносят, и сразу крутится барабаном (`Odometer` с `reveal`), финальное значение держится читаемым ≥1 с до склейки.
- **Текст фразами**, синхронно с голосом, ключевое слово загорается цветом на своём слове. Не по одному слову («висит одно The»).
- **Отступы.** Подпись не касается полос, линий, иконок, 3D-объектов: ≥16 px при 1920×1080; текст в плашке с внутренними полями; оси и границы не проходят сквозь подписи; суммы не лежат на карте поверх территории.
- **Края кадра.** Важное ≥60 px от края, заголовки ≥100 px; ничего не торчит наполовину за кадром дольше входа/выхода; цифры не обрезаны.
- **Переходы.** Резкие (сдвиг/склейка), без мутного наложения двух макетов. В `Shell`: уходящая сцена растворяется по всему overlap (`prog(f, dur-10, dur-1, E.inOut)`), входящая поднимается с 2-го кадра. Элементы новой сцены не появляются на полной непрозрачности поверх текста старой.
- **Удары.** На hit/boom/stamp в звуке: толчок камеры и лёгкая вспышка экспозиции; парящая пыль, тёплая засветка в начале глав, зерно. Палитра: тёмные чернила + кремовый, золото, красный; шрифты Instrument Serif + Inter Tight + IBM Plex Mono. Разбавлять тёмную палитру «бумажными» сценами.
- **Никаких «рисунков кружочками».** Любой предмет, который в кадре крупно (еда, товары, здания, машины), делается фотореальным 3D. Иконки допустимы только как иконки: единый линейный стиль, контур строится из настоящей формы (shapely union), а не из наложенных кругов. Примитивные «коробки» вместо зданий владелец считает браком.

## Blender без GPU: как делать фотореал дёшево
- Python-модуль `bpy` (Python 3.11 venv), `blender/lib.py` (свет, камера, shadow catcher, материалы, отражатели), Cycles CPU 24–64 сэмпла + OIDN, AgX, `film_transparent`, для стекла `film_transparent_glass=True`.
- **Спрайт-развёртка вместо анимации.** Объект рендерится один раз как поворот (yaw sweep, шаг 2–5°) ортокамерой с фиксированным наклоном: `obj_###.png` + отдельный проход тени `sh_###.png`. В Remotion соседние углы кроссфейдятся через `mix-blend-mode: plus-lighter` в `isolation: isolate` (не просвечивает). Тени перьевать (`tools/feather_shadows.py`), иначе режутся краем кадра.
- **Статичный герой** = один кадр развёртки + тень, сплющенные и обрезанные по bbox (`tools/make_art.py`), в React он вписывается по bbox объекта. Тёмное состояние через `filter: brightness/saturate`, а не отдельный рендер.
- **Органика (еда)** не из метаболов (выглядит тестом): SDF в numpy (smin/smax, эллипсоиды, конусы) -> marching cubes (scikit-image) -> PLY с запечёнными цветами вершин (подрумянивание по высоте, складкам, шум) + материал с крапинками, coat, bump. Нормали после импорта: `normals_make_consistent`, иначе крыша машины рендерится стеклом.
- **Целая сцена (улица) = фиксированная ортокамера.** Плита (фон) рендерится один раз, подвижный объект отдельной развёрткой той же проекцией; положение в кадре — аффинная карта метры -> пиксели (`map.json`: origin, ex, ey, ez). Путь машины в метрах (Эрмит + дуга поворота), свет фар рисуется полигоном в координатах улицы, screen-blend.
- **Металл/золото** без отражателей чёрный: эмиссионные плоскости, невидимые камере и диффузу, light linking.
- **Текст в Blender:** woff2 перевести в ttf через fontTools и сделать `removeOverlaps`, иначе буквы ломаются (`GЯOCERY`). Проверять каждую вывеску крупным кропом.
- Время: 35–110 с/кадр. Сцена улицы целиком ~15 мин на плиту. Длинные очереди ставить фоном через `setsid nohup` со своим логом и маркером «done».
- Сток: замедление смешиванием соседних кадров, ускорение усреднением, push-in кропом из 4K, общий грейд. Не пересглаживать (в v3 склад вышел мыльным).

## Контроль качества (обязательно до отправки)
1. **Стоп-кадры** нужных кадров: `GL=null ENTRY=src/solo/<ch>.tsx node stills.mjs <out> ch-<ch>:f1,f2,...`, склеивать в контакт-листы и смотреть глазами. Для каждой правки: старт сцены +5/+15/+30/+45/+60/+90 и стыки с соседями.
2. **Покадровый аудит всего ролика** перед каждой версией: листы по сценам (`review/scenes.py` -> scenes.json), поиск по классам: overlap, static_start, clipped, offscreen, overflow, misaligned. В v3 так нашлось ~115 дефектов (37 наложений, 36 мёртвых стартов, 11 обрезанных, 10 за краем). `review/motion.py` по разнице кадров находит застывшие участки.
3. Если разрешена мультиагентная работа: по агенту на главу с брифом `review/BRIEF.md` (правят только свой файл главы, общие компоненты меняются централизованно после них, список общих правок в shared_todo).
4. После финального рендера: ffprobe (2560×1440, длительность), 5–8 кадров из готового mp4 по изменённым сценам.

## Ошибки, которые уже стоили времени
- 925 МБ файл пропал из папки проекта -> всегда двухпроходное сжатие до ~280 МБ.
- `while pgrep -f "render_job2.sh hunt"` совпал с командной строкой запустившего шелла и ждал вечно (потеряно 2 ч). Писать скрипт пайплайна файлом и ждать по PID или по маркеру в логе, не по pgrep с текстом, который есть в собственной команде. Так же `pkill -f` убивает собственный шелл.
- Маска (`WebkitMaskImage`) на слое, который двигается translateX, обрезала край плиты: маску вешать на внешний неподвижный AbsoluteFill, сдвиг на внутренний.
- Фонари парковки закрывали вывеску, голубая полоса неба над землёй, «белые ставни» вместо витрин: каждую 3D-плиту смотреть целиком и крупными кропами до рендера глав.
- «Висящий ноль» у счётчиков, мутные переходы, пустые первые кадры сцен — первые замечания владельца, проверять в первую очередь.
- Удалять файлы с glob через rm блокируется: писать в новые каталоги или удалять по точным путям.
